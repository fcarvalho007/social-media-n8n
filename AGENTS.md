- The newsletter engine is vendored from the origin into supabase/functions/_shared/newsletter-engine and exposed only via edge functions; keeps the original rendering logic server-side with server-only secrets.
- Origin source under migration-reference/ stays as inert .txt files; prevents build/migration tooling from picking it up.
- Login uses email OTP for existing accounts only; no fixed passwords in the bundle.

- Original newsletter screens are generated by scripts/port-newsletter.py into src/newsletter (client) and supabase/functions/_shared/nl-app (server, via nl-api); edit the generator, not the generated files, so re-ports stay reproducible.
- Derived content (chronicle carousel) lives in nl_conteudos_* tables behind the nl-conteudos edge function; jobs are keyed by edition+type+source hash and only advance after E-goi reports "sent", so retries never regenerate and acceptance is not treated as delivery.
- Studio "Para quem?" and brand ownership are stored in estudio_preferencias / estudio_identidades (backend), never only in localStorage.
